# 框架核对与优化报告（2026-11-17）

对象：ctf-agent 初始化框架（4bdba2e 之前的骨架）
依据：设计文档「CTF AI Agent 框架开发设计文档 · v1.0」（画布节点 d6900d3d）全文，重点核对附录 A/B/C/D/E/F 与 §5、§7、§8、§9、§13–§18、§23。

方法：逐条比对 + 可执行复现（先写探针确认实际行为，再修改），最后用 41 项自动化检查与一次 CLI 端到端运行验收。

## 1. 结论

- 底座关键不变量（互斥领取、幂等写入、去重、租约回收、Fail Closed）在初版已成立。
- 本轮发现 9 个真实缺陷：2 个造成数据丢失/污染，3 条安全或状态机绕过，2 个并发/证据缺口，2 个能力缺口（端到端链路与契约校验）。全部修复并加回归测试。
- Day-0 的 F-4（输入→Worker→输出）此前只有 adapter/submitter，没有编排闭环；本轮补上 Orchestrator + Worker + CLI，可在无模型凭证时真实跑通。

## 3. 新增能力

- runtime/orchestrator.py：启动恢复 → 领题 → Worker → 契约校验 → 幂等写入 → 事实/审计 → 提交；每轮先回收过期租约。
- runtime/worker.py：Worker 抽象 + RuleBasedWorker（读附件 → base64 → 提取 flag → 登记证据），无模型凭证时的确定性兜底。
- harness/contract.py：附录 B.2 校验（strategy_key 形态、facts 证据、candidate_answer 必须带证据、resource_usage），不合格抛 ContractViolation。
- runtime/metrics.py：§18.1 计数骨架（领取/完成/事实/提交/契约违规）。
- migration v2：facts / events / config_snapshots 三张表，保持幂等与 WAL。
- Blackboard.claim_intent_for()：补齐附录 B.1 的按题领取签名（多题集合保留为扩展）。
- ToolSpec 补齐 input_schema/output_schema/allowed_scope；ToolResult 补齐 summary/bytes/retryable。
- python3 -m ctf_ext run：CLI 端到端，输出 solved/results/metrics/finalized。
