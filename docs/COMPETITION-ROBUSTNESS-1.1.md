# 4 小时 CTF 工程鲁棒性优化 1.1

日期：2026-11-19。范围：仅授权 CTF；评审建议、补齐现有证据/上下文与预算恢复，不重写解题引擎。

## 1. 结论：采纳目标，修正绝对化方案

优化目标建议改为：在赛事规则、授权范围、总时限及资源上限内，提高单位墙钟时间产生的**平台接受分数**，同时约束误提交、无效调用和恢复损失。排名取决于对手、题目及计分规则，不能作为框架可以保证的验收结果。

本轮没有启用固定五路 Agent，没有增加真实模型请求，没有更改参赛配置或调用官方提交接口。现有未提交的 Python 执行工具等改动保留，不作无关重构。

| 原建议 | 评审 | 优化后的执行原则 |
| --- | --- | --- |
| 单 Agent 已被证明不够 | 不采纳此绝对结论 | 保留资源匹配的单 Worker 基线；Planner、上下文隔离与专家委派分别验证，不把多 Agent 当作收益来源本身 |
| 非执行 Planner + 瞬态专家 | 有条件采纳 | Planner 负责决策；确定性控制器掌握预算、授权、状态迁移和提交权；专家必须返回有来源的交接包 |
| 每题固定 5 个并行 Agent | 不作为默认 | 跨题覆盖优先；题内对冲是独立开关，要求不同假设、独立工作目录、共享硬预算、取消能力与全局模型限流 |
| 仅通过温度制造多样性 | 不够 | 优先改变假设、观测方法及技能；温度和思考参数只在当前 Provider 明确支持时使用，不猜接口能力 |
| 事实-意图 DAG 唯一真相源 | 采纳外置状态，不要求立即重建 | 当前 SQLite/证据库继续权威；未来追加依赖关系与版本化事实，DAG 是可重建视图，不和交易状态并列维护两套真相 |
| 正则提取后强制回填 | 采纳但不能升级可信度 | 关键观察卡携带 evidence_id、command_id、UTF-8 字节偏移和候选类型；原文不丢；有配额；候选始终不可信 |
| 每题容器与 checkpoint | 采纳 | 真容器、进程取消和恢复测试是前提；工作目录隔离不等于容器；checkpoint 不代表可以无副作用重放 |
| L1 精确缓存 + L2 语义缓存 | 仅确定性 L1 自动复用 | 缓存须考虑输入内容、目标版本、环境、身份/会话和 TTL；L2 只用于检索历史线索，不能替代目标实时观测或提交验证 |
| Planner 永远不升级 | 不采纳为通则 | 默认轻量；规划错误可先规则纠错或重置，再评估是否升级；全部受模型许可与预算约束 |
| 12 次动作没有 flag 才升级 | 不直接移植 | “未得到最终 flag”不等于停滞。以经验证的子目标、假设排除、环境故障和重复观测分流；升级不是故障重试 |
| 每题统一 600 秒、固定调用数 | 仅作为待测配置 | 使用全局截止 + 共享调用/Token 账本 + 单题软租约 + 硬上限；按题类及实测 P50/P95 校准 |
| 30/50/70/100、相似度 0.85 | 不作为普适常数 | 保留既有候选阈值便于对照，不因文章建议擅自改值；相似度只作信号，结合目标/输入/状态变化判断 |
| 没证据宁可不交 | 作为自主提交安全策略采纳 | 可保留人工复核候选；不要宣称所有赛事“不交必然比交错好”，应核对限次、扣分与速率规则 |

## 2. 研究依据核查与边界

### 2.1 Intentest：数据有依据，但不是本项目成绩

原论文为《Staying on the Attack Path: Structured State for Long-Horizon Automated Penetration Testing》，arXiv:2609.07344，2026-09-07 首投、2026-09-18 修订。摘要确实报告 88.2% 总成功率；意图检索/预测消融在**已成功的中、难题**上平均轮次分别减少约 33%、48%，可解题集合未变。

应据此支持外置状态与受前提约束的检索，而不是推导“相同 Token 下竞赛解题数必然增加同样比例”。轮次、Token、墙钟和分数是不同指标；其 Web 任务结果也不是全类别 CTF 的统一表现。不要与 API 意图完整性测试的同名 IntenTest（arXiv:2506.07524）混淆。

来源：https://arxiv.org/abs/2609.07344

### 2.2 Planner-directed：12 次规则不能称作精准升级

2026-11-05 发表的《Planner-directed multi-agent LLMs with on-demand skill-equipped specialists for CTF-based autonomous penetration testing》确实使用持久非执行 Planner、瞬态专家、分层记忆与 episode 内粘性升级，而且**同时只有一个专家活跃**，不是每题五路并行。

它的 12 次无接受 flag / 提交被拒等升级规则在 200 题中触发了 **199 题**，升级模型占花费 **72.5%**。因此，机制名虽为 stall-triggered，也不能据此声称它只在少数值得投入的节点精准花钱。其预算匹配实验未发现架构主效应，且多智能体协调开销抵消了额外解题优势；不能再用该文支撑“单 Agent 已被证明不够”。

原文还将 41 个平台接受结果经来源审计修正为 29 个 genuine solves，说明“平台接受”和“按预期路径真实解出”在公开基准评估中也应分别计数。

来源：https://link.springer.com/article/10.1007/s10207-026-01350-x ，重点见摘要、§3.6、§4.4、§5。

### 2.3 RoMA-CTF：资格矩阵不是同模型提示词收益保证

检索到的 IEEE 摘要片段支持“先度量各模型在题类上的能力，再分配角色”。但 IEEE 正文页面返回访问限制，本次没有取得全文；不核定模型数量、资格矩阵细节或收益幅度。把异构模型角色分配转化成同一 DeepSeek 的类别提示词/思考配置，是本项目可以测试的工程假设，并非本次已核实的等价方案。

来源：https://ieeexplore.ieee.org/abstract/document/11582070

### 2.4 五路并行与缓存 30%

找到了腾讯云开发者社区的相关文章，但没有在本次核查中取得对应的一手实验配置、原始轨迹与收益归因材料；不把二次报道中的五路、30% 或名次作为性能承诺或默认参数依据。它们只作为待测候选，不进入正式准出结论。

## 3. 修订后的分层架构

1. **确定性控制面**：全局截止、资源额度、领取租约、授权范围、提交 Outbox、恢复状态机。LLM 无权提高预算、解除限流或绕过 Gate。
2. **轻量规划面**：题目分诊、假设优先级、暂停/恢复决策。先使用现有 IntentPlanner，不为采用论文而新增常驻多角色对话。
3. **按题隔离的执行面**：题内默认一个 Worker；技能按需加载；工具只能访问授权题目。跨题并行与题内多路竞赛必须分别验收。
4. **证据与记忆面**：原始输出内容寻址归档；活跃上下文只放有界预览、关键观察和检索指针；观察、推断、验证结论分开。
5. **独立提交面**：candidate → evidence-grounded/local-checked → queued → sent/unknown → accepted/rejected。现有 Gate 的 confirmed 只代表本地校验通过，绝不是平台已接受。

事实可采用追加记录保持历史不可变，但“事实当前仍成立”须绑定目标版本、时间与前提；新证据允许 supersede/retract 旧结论。不要把过期凭据或已重置目标的状态当作永久事实。

工具输出、附件和网页都只作为不可信数据。关键观察正则命中、多人投票及完整命令回显均不能单独证明语义真实性；例如模型自己打印候选，再回读打印结果，是有出处但没有独立支持的循环论证。此风险需要后续数据流来源审计，不能宣布现有 Gate 已杜绝。

## 4. 四小时资源与调度策略

- 全局绝对截止固定；重启不能获得新的四小时窗口；具体预留给提交查询/清理的时间由赛事协议与实测延迟决定。
- 初始分诊使用有界轻量探测；先产出粗分类与可行动线索再逐步更新，避免在分诊本身花掉主要预算。
- 建议以“下一时间片可增加的期望接受分数 / 增量墙钟”排序，扣除切换成本并考虑资源占用；未校准置信度只作相对排序，不能视作真实概率。
- 单题软租约到期返回控制面，而不是删除题目状态；有证据的接近突破可申请续租，但不能突破硬预算。
- 停滞分四类：基础设施错误 → 有界退避；重复观测 → 缓存/回读；假设被排除 → 换路径；有明确子目标但推理不足 → 才考虑许可范围内模型升级。
- “新增输出文件/新哈希/新摘要”不是有效进展。有效进展需要证明满足一个子目标、可复现实验改变已知状态，或有依据地排除一个假设。
- 若试验题内对冲，应比较 1/2/更多路在**相同总 Token/时间额度**下的接受分数、取消尾部成本与互相干扰，不把 5 路设为默认。
- 真实官方接口、模型并发与隔离尚未验收前，不把配置容量解释成可用吞吐。

## 5. 优先级重排

| 优先级 | 工作包 | 准出证据 |
| --- | --- | --- |
| P0 | 官方任务/附件/提交回执闭环 + 单一 Gate/Outbox | 从空库到真实接受；断线未知状态恢复不误重发；不把候选算成功 |
| P0 | 全局硬截止、实耗账本与取消 | 重启不洗白；多控制器累加不丢账；并行前补原子额度预留和全进程取消 |
| P0 | 原文归档、关键观察有界保留与证据来源 | 尾部 flag 不因截断丢失；缓存回读一致；摘要不充当原文；无自打印洗白 |
| P0 | 每题真实隔离与恢复 | 跨题 canary 不串；无越权出口/宿主挂载；中断后副作用不重复执行 |
| P1 | 分诊、暂停/续租及多维停滞分流 | 相同资源预算下无效调用占比下降，不误杀有价值长链路 |
| P1 | 类别技能与受预算约束的升级 | 按类基线、升级触发率/收益/成本可审计；不因普通网络故障换模型 |
| P2 | 题内多路径对冲与语义检索 | 在 P0/P1 可用后进行预算匹配消融，证明净收益再启用 |

缓存与预览不必机械地全列为 P2：若它们正在造成证据丢失或错误复用，就是 P0 正确性问题；只有纯性能增强才是后续优化。

## 6. 本轮实际落地

### 6.1 关键观察预览

- 新增 llm.compress.tool_output_preview，LlmWorker 工具结果正文按 **UTF-8 字节**限制，而非字符数。
- 超长输出先扫描常见 flag/CTF 包裹、JWT、私钥头和数据库连接串，附有界的候选观察卡及原始字节偏移；保留 evidence_id/command_id。
- 最多八条观察、每类扫描候选有上限；不承诺覆盖所有自定义 flag、编码凭据或所有候选。私钥观察卡只额外保留头标识，不扩散整段私钥。
- 卡片明确“不可信、未验证”；不自动声明、不自动提交、不修改 Gate 判定；短输出不改写。
- 此次仅覆盖工具预览；尚未完成跨意图/跨压缩的关键事实索引和自动回填，不能称作完整分层记忆系统。

### 6.2 原文归档修复

现有 ToolRegistry 的 summary 策略曾只归档前 12,000 字节。模型可以看见原文尾部候选，但证据回读/Gate/缓存只见截断版，这是根因级不一致。

本轮改为 raw/summary 均归档执行器返回的完整有界文本；摘要只用于活跃上下文。hash_only 仍不存原文。执行器已截断、失败或超时的结果仍不构成完整成功证据，不扩张其权限。

未修改证据体积上限，也未承诺保留非 UTF-8 命令输出的原始二进制字节：当前执行边界仍以解码后的文本为主。历史已截断证据不能凭空恢复，旧缓存需过期或重新采集后才能取得完整输出。

### 6.3 全局 Token 账本修复

- 重启即从持久用量判断 exhausted；**恰好等于上限**也禁止新调用。
- 不再把损坏账本或数据库读取错误当作零消耗；明确报错，失败关闭。
- 同事务读取并累加，避免多个对象/连接使用旧内存快照覆盖累计量。
- 关闭全局限额时仍记录实际用量；后续恢复额度时不会丢掉这段消耗。
- 单题 remaining.tokens 取单题与全局余额较小者，约束下一次请求的输出上限。
- 这是**调用后实耗账本**，不是调用前原子预留；并行在途请求仍可能超额，Provider 输入 Token 也不由 max_tokens 自动封顶。禁止把它表述为“严格防止全部成本超支”。

## 8. 尚未实现与验收的边界

完整事实-意图依赖图、子目标级进展判定、跨压缩关键事实索引、episode 粘性升级/额度持久化、模型请求前全局原子预留、题内多路竞赛、进程级强制取消、生产每题容器以及 4 小时真实混合题验证均不属于本轮已完成项。

当前 SessionControl.progress 仍以新证据 ID 作为进展近似，时间戳/随机内容可能制造伪进展；不应声称已实现语义级停滞检测。现有 Pro 路由仍是阶段触发、内存计数，不能称作本文建议的完整升级控制器。

配置与官方准出条件保持原样：不放开未验收能力、不静默修改模型许可、不将离线回归当作竞赛解出率。
